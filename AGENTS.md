> **Patterns now load-bearing:**
> 1. **`safe()` helper for per-sub-query fault tolerance.** When a server action aggregates N independent sub-queries via `Promise.all`, wrap each in `safe(() => loader(), fallback)` so one failure becomes a per-slot null rather than a 500. Reusable for any future aggregator with independent slot semantics.
> 2. **React `cache()` for action-level dedup.** Wrap the aggregator's body in `cache()` and re-export via a public action stub. Components that need slices of the result share one round-trip per request.
> 3. **Consolidated chrome + row builders in one file** (vs 1 file per panel). Five categories × <30 LOC of presentation = sensible single-file orchestrator. Premature file splitting was the spec's instinct; consolidation is cleaner.
> 4. **Inline empty hero in same client component as filled state.** Both states share the same outer chrome container — full-height column never collapses on empty.

> **Patterns now load-bearing (hive card redesign additions):**
> 1. **Correlated subquery wins over LATERAL for json_agg + ordered slice.** When projecting a top-N child set per parent row, the LATERAL JOIN with `json_agg(... ORDER BY ...)` redundantly re-sorts a slice that's already ordered+limited inside the subquery. Cleaner: `COALESCE((SELECT json_agg(json_build_object(...)) FROM (SELECT ... ORDER BY ... LIMIT N) sub), '[]'::json)`. Pattern reused across `hive.actions.ts` (T1) + `hives-rail.actions.ts` (T7) + `hives-suggested.actions.ts` (T2).
> 2. **3-tier ranking with parallel-after-await composition.** Multi-tier query where later tiers depend on earlier tier ids: `await tier1Q` first, then `Promise.all([tier2Q, tier3Q])` with the resolved ids interpolated as `sql.join(...)` IN-clauses. Empty-list guard: pass `sql\`NULL\`` so `h.id NOT IN (NULL)` is vacuously true (Postgres-valid, no rows excluded). Reusable for any future ranked-recommendation surface.
> 3. **Single canonical card across multiple route trees.** `components/hive/hive-card.tsx` is the third app-wide shared card (book card + spark card + hive card). Pattern: shared component at `components/<entity>/<entity>-card.tsx`, prop adapters at consumer sites (hub vs discover) handle the few prop differences. Cascade-update across all consumers becomes a single-file change.
> 4. **`showRolePill: false` for tab-implicit role.** When a card's role pill duplicates information already conveyed by the tab/route context, suppress it via an optional prop. On `/discover` surfaces, all cards are "discoverable" by definition — role pill is tab-implicit.
> 5. **Markdown-bold parsing for server-rendered text.** When a server-fetched string contains `**bold**` markers, parse via regex split (`/\*\*(.+?)\*\*/g`) into a tokenized array of strings + JSX `<strong>` elements. No need for a full markdown parser. Used for the why-suggested line.
> 6. **`<RailPanel>` polymorphism via optional style props.** When a small inline helper needs to support both default (natural-height stacked) AND alternate (flex-fill with internal scroll) layouts, add 3 optional CSS-prop slots (`style`/`headerStyle`/`bodyStyle`) rather than forking the component.

## ✍️ Copy & Voice rule (load-bearing for ANY user-facing string)

**No em-dashes (`—`, U+2014) anywhere users can read.** This is a project-wide style rule decreed by Chris (2026-06-10). It applies to:

- JSX text children
- `placeholder`, `title`, `aria-label`, `alt`, `label`, `description` props
- Toast messages, error messages surfaced in UI, confirmation prompts
- Page `<title>` and `<meta description>` content, email subjects/bodies
- Anything else a user can read (including screen-reader-only labels)

**Rewrite patterns** — preserve meaning, never use em-dash:
- `"Foo — bar"` (parenthetical aside) → split into two sentences, use commas, or parens
- `"Foo — bar, baz"` (list intro) → colon (`"Foo: bar, baz"`)
- `"Optional — edit later."` → period or comma (`"Optional. Edit later."`)
- `"Field — required"` → parens (`"Field (required)"`)
- `"X — Y"` (attribution) → comma or `by` (`"Quote, by Author"`)

**En-dash (`–`, U+2013) is fine for number ranges** (`"3–24 characters"`, `"Mon–Fri"`). Only U+2014 is banned. Hyphens (`-`) are fine everywhere.

**Internal scope NOT affected** by this rule: code comments, `console.log/warn/error`, AGENTS.md, docs/, specs, plans, dev-only scripts, migration narratives, design mockup HTML. Em-dashes there are dev-facing and stylistically free.

When writing new UI copy, just don't reach for `—`. When editing existing UI strings that contain one, rewrite as part of the same change.

**Patterns now load-bearing across the codebase:**
1. **Multi-row notification fan-out** via single `tx.insert(notifications).values(recipients.map(...))` batch from `tx.select(...)` lookup of OWNER+MOD members — captures "notify all admins" semantics in one round-trip. Reusable for any future role-based notification pattern (e.g. C5 mentions notifying all moderators).
2. **Insert-as-QUEUE-first-then-deriveCurrentBookTx pattern** for partial-unique-index-safe CURRENT promotion — any future "at most one X per parent" pattern with denorm pointer follows this shape. Direct-insert-as-CURRENT would violate the partial unique constraint.
3. **`deriveCurrentBookTx(tx, opts)` atomic 4-step pattern** consolidates find-existing-CURRENT → flip-to-PAST + finished_at → flip-target-to-CURRENT + started_at → update denorm `current_book_id` pointer → fire activity event gated `PUBLIC && discoverable`. Reusable for any future "promote one row to active among siblings" flow.
4. **Drop-and-readd FK pattern** for forward-reference table circular deps — `book_clubs.current_book_id` FK on `book_club_books.id` defined as a separate migration step since `book_club_books` table is created after `book_clubs`. Pattern lives in migrate-c4 step 14.
5. **`listClubMembersAction` OWNER→MOD→MEMBER role ordering** via raw `case ${role} when 'OWNER' then 0 when 'MODERATOR' then 1 else 2 end` SQL — codebase precedent for "sort by enum priority then chronological". Reusable for any role-based listing.
6. **Cross-feature component imports** (Discover importing `<ClubCard>` from `(app)/clubs/_components/`; profile importing same) — pragmatic colocation precedent set in C3 with `<ListCard>` and continued in C4. Acceptable when the source is presentational + stable; refactor to a `components/` shared module only if a third consumer arrives.
7. **`canReadBook` positional signature** `(bookId, viewerUserId) → { ok, reason? }` continues to be load-bearing — never use object-arg form. Caught again in C4 T7's `addClubBookAction` validation.
8. **List-action shape** `{ rows: Array<{ id, ...profileShape, createdAt }> }` for admin-panel queries — used by both new W7 actions. Profile shape via leftJoin to userProfiles with explicit username/displayName/avatarUrl projection. **Bugs caught + fixed mid-stream:**
- T6 first cut captured `readSet` by closure for rollback. Walking the scenario: user clicks A (snapshot `{}`, optimistic `{A}`) → user clicks B before A resolves (snapshot `{A}`, optimistic `{A, B}`) → A's action fails → rollback `setReadSet({})` wipes B silently. **Fix:** [e1c6797](https://github.com/Cremacious/beehive-studio/commit/e1c6797) switched BOTH the optimistic flip AND the rollback to functional updaters `(prev) => ...`. Rollback inverts only `binderItemId`'s flip against `prev` instead of stomping the entire set. `wasRead` still captured at click-time because it represents user INTENT, not global state. `onReadSetChange?.(set)` lives inside the updater body so the parent always sees the same value the state lands on — pragmatic violation of React's "updater must be pure" guideline accepted for the live-stat-sync contract.
- T2 surface-shape tests used `await import('@/lib/actions/reading.actions')` inside each `it()` block. Solo runs passed in ~2.7s; under full-suite parallel load the module-graph parse exceeded the 5s vitest default and timed out — T2 reported 427/427 green when full-suite was actually 426/427. **Fix:** [ca51b28](https://github.com/Cremacious/beehive-studio/commit/ca51b28) hoisted to a single top-level static `import * as readingActions` after the `vi.mock` declarations. Tests now resolve in ms once the module graph is parsed.

**Patterns now load-bearing across the codebase:**
1. **`chapter_reads` is the per-chapter read truth.** Never derive reads from `readingProgress.chapterId` linearly — that table is the cursor only. Any new read-related query should join `chapter_reads`, not walk binder item order.
2. **`markChapterReadAction` is the ONE place that bridges read-set + cursor.** Both writes happen in the same call so the auto-mark from `/read/[chapterId]` keeps populating both tables atomically. Don't add a separate "set cursor" action.
3. **Server actions take `chapterBinderItemId` everywhere.** The chapters PK (`chapters.id`) is now exclusively a `readingProgress` cursor implementation detail. UI + new actions must pass `binderItems.id`.
4. **Optimistic-toggle rollback uses functional updaters, never captured snapshots.** Pattern: `setReadSet((prev) => invertOnlyTheOneRowYouChanged(prev, id))`. Captured `setX(state)` for rollback stomps concurrent successful toggles.
5. **Sticky scroll-spy via IntersectionObserver** uses `rootMargin: '-80px 0px -60% 0px'` + threshold `[0, 0.25, 0.5, 0.75, 1]` + section-id-keyed observation. Future stacked-section pages should reuse this exact tuning.
6. **`<ReaderPageShell>` pattern** — when two stacked sibling sections need to share optimistic state (e.g. a stat in one updates from a toggle in another), wrap them in a client component that lifts state via `useState` and threads `readCount` / `onReadSetChange` callbacks. Use `Omit<ComponentProps<typeof X>, ...>` for prop typing so wrappers stay in sync.
7. **Share URL composed from headers (not env vars)** — `${proto}://${host}${path}` from `x-forwarded-proto` + `host` works in dev (localhost) AND prod without coupling.
8. **`PublicBook & { extra1; extra2 }` intersection** is the pattern for client components that need fields not on the source type — the page orchestrator supplements via sibling fetches and passes the widened object.
9. **Surface-shape tests use top-level static imports** after `vi.mock` declarations. Dynamic `await import()` per test times out at the 5s vitest default under full-suite parallel load.
10. **Test pattern for refactor commits:** mirror `lib/actions/__tests__/create-hive-action.test.ts` shape — `vi.mock` `@/lib/require-auth`, `@/lib/books/can-read`, `@/db`, then assert exports + arity. Behavior tests are gated by manual smoke per Chris's preference.

### Drag-into-Folder ✅ COMPLETE (2026-05-28)

Extends the binder's existing dnd-kit setup with nesting. Dropping a document onto a folder row nests it; existing sibling-reorder behavior preserved.

**Accept rules** (`lib/binder/drop-rules.ts`):
- `part` (collection) accepts only `chapter`
- `research_folder` accepts every non-chapter document type: `research_note`, `research_folder` (sub-folders), `character`, `outline`, `front_matter`, `back_matter`
- Non-folder types are top-level only
- Cycle guard walks `parentId` upward from the target — rejects if active.id appears in the chain (with a `seen` Set defense against corrupt data)
- Pure helpers (`getAcceptedChildTypes`, `canNest`, `classifyDropZone`) unit-tested in isolation in `lib/binder/__tests__/drop-rules.test.ts`

**Mechanism** (lessons learned from a hairy debugging session — see `ff3e711` commit message):
- **NO `verticalListSortingStrategy`** on SortableContext. The strategy makes rows shift out of the way during drag to preview the new position — which made folder rows vacate when the user tried to hover them as nest targets. Sortable still tracks reorder logically; items just snap to the new position on release rather than animating during drag.
- **Custom collision detection** (`pointerWithin` → `rectIntersection` composition) using real pointer Y from a global `pointermove` listener. `closestCenter` doesn't work here because the dragged ghost's center is offset from the user's pointer by their grab offset, so it consistently resolved `over` to a neighbor instead of the folder under the pointer.
- **Separate `:nest` droppable overlay** on folder rows (NOT in SortableContext, so it doesn't participate in sortable reorder). Overlay element is absolutely positioned at `top:3, bottom:3, inset-x-0, pointer-events-none` — covers ~87% of the row. When the pointer is over the overlay, custom collision detection prefers the `:nest` id (suffixed `${node.id}:nest`) over the sortable's id. `handleDragOver` / `handleDragEnd` strip the suffix to recover the logical folder id.
- **`setNodeRef` on the row only**, not on a wrapper containing the row + children. Otherwise an expanded folder's droppable rect spans its entire subtree and `closestCenter` (or any rect-based collision) picks children instead of the folder itself.

**Three drop zones per row** (`classifyDropZone`): folders get top 3px = reorder before, middle = nest into (via `:nest` overlay), bottom 3px = reorder after. Non-folder rows split at vertical midpoint (before/after only). The 3px edges make the nest band ~87% of the row, so users don't need precise alignment.

**Visual indicators** (`binder-item.tsx`):
- Reorder before/after: thin brand-yellow horizontal line above/below the row (`h-0.5 bg-brand rounded-full mx-2`)
- Nest target: row gets `ring-2 ring-brand bg-brand/20` + a 4px brand-yellow halo via `shadow-[0_0_0_4px_oklch(from_var(--brand)_l_c_h_/_0.25)]`. The halo makes the locked-on folder visually pop forward.
- All rendered via a `dropZone: { overId, zone } | null` field on the existing `BinderTreeContext`.

**Auto-expand** (`binder-tree.tsx`): middle-body hover on a collapsed folder for 500ms expands it. Implemented with two `useRef`s (timer + target id) so re-hovering the same folder doesn't reset the countdown. Timer canceled on drag end, on invalid hover, and on any guard-return path inside `handleDragOver`.

**Drop behavior** (`handleDragEnd`): branches on the captured `dropZone`. `middle` → `parentId = folderId, order = maxOrderInFolder + 1` (no sibling reshuffle). `before`/`after` → adopts `overItem.parentId`, splices at the correct insertion index, recomputes orders. All updates flow through the existing `reorderBinderItemsAction` — no server-action changes.

**Pattern notes for future dnd-kit work in this binder:**
- Don't use `verticalListSortingStrategy` when you also need "drop ON" semantics. The strategy and "drop ON" are fundamentally incompatible.
- Use `pointerWithin` + a tracked `pointermove` ref when the dragged ghost's center may be offset from the user's pointer (which is almost always).
- For "drop ON" targets that overlap with sortable items, use a SEPARATE `useDroppable` NOT in SortableContext, with an overlay element covering the target band. Prefer the overlay id in collision detection. The non-sortable nature of the overlay is what stops the underlying sortable from reordering.
- `setNodeRef` MUST go on the visual click target itself, never on a wrapper that also contains descendants — otherwise the droppable rect doesn't match the visual target.

No DB / schema changes. 157/157 tests (137 baseline + 17 helpers + 3 net updates), tsc clean. Two non-blocking concerns noted: timer cleanup on unmount (low risk; would require `useEffect` cleanup hook), and `.find()` perf on very large binders (Map lookup would be cheaper). Both deferred.

**Out of scope (deferred):** soft-delete with undo toast (real delete only), type-to-confirm (simple confirm matches existing app vocabulary), bulk delete, hive-shared book handling.

**Pattern for future "shared trigger + dialog" wiring:** the `DeleteBookButton` render-prop shape — `children: (onTrigger: () => void) => React.ReactNode` — is the cleanest way to share a confirm/action/redirect flow across multiple visual triggers (menu item vs button). Plug-in trigger receives an `onTrigger` callback to open the dialog; the wrapper owns all the state and side effects.

### P8A Stripe pattern
Premium derives from `userBilling.subscriptionStatus IN ('active', 'trialing')` — no denormalized boolean. Stripe customer creation is lazy (first checkout creates the customer; stored on `userBilling.stripeCustomerId`). `lib/stripe/client.ts` is the singleton with pinned `apiVersion` + runtime key-prefix sanity check (`sk_live_` in prod, `sk_test_` in dev). Webhook endpoint at `/api/webhooks/stripe` is signature-verified but no-op in P8A (P8C wires handlers — do NOT configure Stripe dashboard webhook URL until then or events get lost). `DEV_FORCE_PREMIUM=true` env override still works for local testing without Stripe.

### P8B pricing pattern
Public `/[locale]/pricing` page fetches Stripe prices server-side with `revalidate: 3600` ISR. PlanCard client component handles the monthly/annual toggle + dynamically computed savings percentage. Logged-in users invoke `createCheckoutSessionAction` and redirect to Stripe; logged-out users go to `/sign-up?next=/pricing` (sanitized via `safeNextPath`). The sign-up page server-checks session and bounces already-authed users to `next` (so authed users clicking Upgrade get straight to /pricing without seeing the form). Stripe success_url points at `/[locale]/welcome` (P8B-shipped celebration page). Until P8C wires real webhook handlers, paid users are technically not premium until P8C catches up — Stripe retries events for up to 3 days.

### P8C webhook pattern
`lib/stripe/handle-subscription-event.ts` is the single entry point for `customer.subscription.{created,updated,deleted}` events. Idempotent by construction (upserts `userBilling`). Race-recovery: if the userBilling row is missing for a `stripeCustomerId`, fetch the Stripe customer's `metadata.userId` and upsert. Throws on unknown subscription status (prevents DB corruption when Stripe adds new statuses) or hard failures; webhook route returns 500 → Stripe retries up to 3 days. **DO NOT add side effects** (welcome emails, etc.) without first adding event-ID deduplication — Stripe retries fire side effects multiple times. Stripe API 2026-02-25.clover moved `current_period_end` onto `subscription.items.data[0]` — handler reads it from there.

### P8D billing/downgrade pattern
`/settings/billing` renders one of 5 state branches based on `userBilling.subscriptionStatus`: free / active+trialing / past_due (warning) / canceled / other. ManageButton invokes `createBillingPortalSessionAction` (P8A). Soft-lock on overflow books: `isBookOverflow(userId, bookId)` from `lib/billing/book-overflow.ts` — non-premium users with >`FREE_BOOK_LIMIT` books get oldest 3 active, others read-only via the OverflowBanner + `editor.setEditable(false)`. createdAt ASC chosen for stability (updatedAt would shift overflow set on every keystroke). `bookOverflow` flows server-page → BookEditorProvider prop → context → ChapterEditor. Hive invite/join actions block when current member count exceeds `FREE_HIVE_MEMBER_LIMIT` — existing members keep editing. `past_due` is treated as premium in `PREMIUM_STATUSES` so Stripe's grace period (~3 weeks of retries) preserves access.
