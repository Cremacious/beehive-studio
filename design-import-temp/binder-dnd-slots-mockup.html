Variant A · Gap slots

Dashed rectangles appear between rows the moment a drag starts. The dragged item lands in whichever gap you release into. Existing rows don't shift — the gap simply "opens up" where the item drops. Hit zone for each slot is roughly the size of a row, so precision is easy.

Variant B · Row-position slots

Every existing row becomes its own dashed slot. Drop onto a slot → your item takes that slot, everything from that point down shifts a peg. Same as iOS table-view reordering. Slightly less obvious where "end of list" is (need an explicit trailing slot).

Folders (both variants)

Folder rows (Knights of Varrock) light up with a solid yellow ring when the cursor is over them — meaning "drop here and I'll nest the item inside". The slot above/below the folder is still a gap-slot for sibling reorder.

What I'm asking you to pick

  1. A or B — which slot model feels right.
  2. Should gap slots ALWAYS be visible, or only while dragging? Default in this mockup: only while dragging (less visual noise at rest). Toggle in the JS if you want me to show always-on slots.
  3. Slot height — current is 22px tall (generous). Could go smaller (~14px) if it feels chunky. Bigger = easier hit, but more vertical space in the binder.
