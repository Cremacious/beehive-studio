08 P1

Card-grid layout inconsistency — auto-fill vs fixed 4-col cap

/studio: repeat(4, ...) max-width: 880px (compact tiles, content-bounded). /hives, /reading-lists, /clubs, /discover: repeat(auto-fill, minmax(280px, 1fr)) (stretches across full viewport). Two patterns for "list of similar cards." Pick one or document when to use each.

4-col capped (/studio) — bounded

Non-visual findings — no mockup needed

  • P0: error.tsx + not-found.tsx use text-[#FFC300] instead of text-[var(--brand)]. Trivial swap.
  • P2 — AppNav no mobile breakpoint: center nav absolute-positioned, will overlap brand + avatar below ~700px viewport. Need a media query or flex restructure.
  • P2 — /discover hero pattern vs /community section rail: two "browse multiple content types" surfaces use different UX shapes. Worth deciding which is canonical.
  • P2 — Auth + /settings/billing + /welcome + /pricing haven't been smoke-tested against the brightness bump. Walk-through pass needed.
  • P2 — /studio editor surfaces (binder, metadata panel, status bar, toolbar) pre-date the design refresh. Brightness bump may affect ink legibility against the cream-paper canvas.
  • P3 — Two create-hive-modal.tsx files: studio/[bookId]/_components/ (stub) and studio/_components/ (real). Delete the stub.
  • P3 — ping-sessions.ts: add header comment explaining it's the Neon connectivity canary so future-me doesn't delete it.
  • P3 — design-import-temp/: 4 mockup HTMLs + a tarball accumulating. .gitignore or archive after ports ship.
  • P3 — <HiveCard> (studio rail) vs <HiveIndexCard> (/hives): two hive cards with overlapping responsibility. Consolidate or document the deliberate split.
  • P3 — Class name collision risk: grep for any remaining single-word component classes (empty, body, meta, title) — prefer prefixed (.bcv-*, .hic-*).
  • P4 — aria-label on icon-only buttons: notifications bell, kebab menus, sort dropdowns. Audit sweep needed.
  • P4 — Form labels: some pages use <p> + style instead of <label htmlFor>. Tab-order + screen-reader navigation impact.
  • P4 — Focus states: brand-yellow focus:ring-2 on modal inputs only; uneven across the app.
